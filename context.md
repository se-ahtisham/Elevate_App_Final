## 1. Project Overview

**Elevate** is a **Flutter mobile app** (FYP — Final Year Project) that connects **Job Seekers**, **Companies**, and **Admins** on a single platform. It combines:

- **Job searching & applying** (internal platform jobs + external API aggregation)
- **Skill testing & certification** (QR-code based test entry, MCQ/theory/coding questions, badges)
- **Portfolio management** (projects with media uploads)
- **Community / social feed** (posts, likes, comments, follow system)
- **Company reviews & ratings** (sentiment analysis, AI-derived strengths/weaknesses)
- **Career guidance tasks** (AI-generated or admin-assigned learning tasks)
- **Admin panel** for full platform management

**Package Name:** `elevate_app`
**SDK:** Flutter/Dart (SDK ^3.8.1)
**State Management:** `flutter_riverpod` (v2.5.1)
**Backend:** Firebase (Auth, Firestore, Storage) + external APIs via RapidAPI + FastAPI backend on Render

## 6. User Roles & Authentication Flow

### Three User Types:
1. **JobSeeker** — Stored in `jobSeekers` collection
2. **Company** — Stored in `companies` collection
3. **Admin** — Stored in `admins` collection

### Auth Flow:
1. **Sign Up** → Firebase Auth creates user → Corresponding model saved to Firestore → Email verification sent
2. **Login** → Firebase Auth sign in → Email verification check → Determine user type by checking collections sequentially (jobSeekers → companies → admins) → Load user model
3. **Forgot Password** → Firebase sends password reset email
4. **Change Password / Email** → Requires re-authentication

### Auth Architecture:
- `AuthService` (`lib/Database/Online_Database/auth_service.dart`) — Raw Firebase Auth wrapper (sign up, login, logout, password reset, email verification, change password, delete account)
- `AuthNotifier` (`lib/Database/Online_Database/auth_provider.dart`) — Riverpod `ChangeNotifier` that wraps `AuthService` + `FirebaseService` + `AdminService`. Exposes `isLoading`, `errorMessage`, `successMessage`, `userType`, `jobSeeker`, `company`, `admin`
- **Providers:**
  - `authStateProvider` — `StreamProvider<User?>` (Firebase auth state)
  - `authProvider` — `ChangeNotifierProvider<AuthNotifier>`

### Admin-Created Accounts:
- `AdminService` (`lib/Database/Online_Database/admin_Service.dart`) uses a **secondary Firebase app instance** (`Firebase.initializeApp(name: "SecondaryApp")`) to create accounts without logging the admin out
- Can create both JobSeekers and Companies

## 9. External API Services

### `JobService` (`lib/Services/job_service.dart`)
- **Purpose:** Aggregates jobs from **JSearch (RapidAPI)** and **Arbeitnow** APIs
- `fetchAllJobs(query)` → Parallel fetch → Clean (deduplicate) → Rank (relevance) → Return `List<ApiJobModel>`
- Uses `Job_Ai_API_KEY` from `.env`
- 15-second timeout on all requests

### `SkillApiServices` (`lib/Services/skill_api_Services.dart`)
- **Purpose:** Fetches 20 trending tech skills from **ChatGPT-42 (RapidAPI)**
- `fetchTrendingSkills()` → POST to ChatGPT → Parse JSON array → Return `List<SkillModel>`
- Uses `Top_Skill_Ai_API_KEY` from `.env`

### `ApiStatusChecker` (`lib/Pages/User_Screens/Admin_Screens/Admin_Api_Management/api_status_service.dart`)
- **Purpose:** Admin tool to check health of all backend API endpoints
- **Live server:** `https://elevate-backend-rtdg.onrender.com` (FastAPI on Render)
- **Local server:** `http://127.0.0.1:8000`
- Checks 8 endpoints per environment: Health Check, Generate Question, Record Answer, Evaluate MCQ, Evaluate Theory, Evaluate Coding, Get AI Logs, Interactive Docs (Swagger)
- Has fallback URL logic (underscore vs dash routes)

### Utility Classes (`lib/utils/`)
- `JobCleaner` — Deduplicates jobs by normalized `title@company` key
- `JobRanker` — Scores jobs by: title match (+5), company match (+2), remote (+2), recency (recent +3)
- `TextNormalizer` — Lowercase + trim for comparison

## 15. Architecture & Patterns Summary

### Architecture:
- **Monolithic `FirebaseService`** — All Firestore operations in a single class (~1400 lines)
- **Riverpod** for state management (auth provider + auth state stream)
- **No repository pattern** — Services accessed directly from widgets
- **Batch writes** used extensively for multi-document operations
- **Transactions** for atomic operations (e.g., like toggling)

### Navigation:
- Each user role has its own `BottomNavigation` with `IndexedStack` + per-tab `Navigator` stacks
- Custom slide route transitions for page transitions
- Material page routes for most navigation

### Naming Conventions:
- Files: `snake_case.dart` (mostly)
- Classes: `PascalCase`
- Directories: `Pascal_Case_With_Underscores`
- Collections in Firestore: `camelCase` (e.g., `jobSeekers`, `followRequests`)

### Design Patterns:
- All models use `toMap()` / `fromMap()` pattern for Firestore serialization
- Models are immutable (final fields) with optional `copyWith()` on some
- Lists default to `const []`
- DateTime fields handle null gracefully with `DateTime.now()` fallback
- Firebase batch operations for multi-document consistency

## 17. Key Business Logic

### Job Recommendation Algorithm:
1. Get all passed test results for a job seeker
2. Map each result to its skill and best score
3. Convert scores to tiers: Gold (90+), Silver (75+), Bronze (50+)
4. Gold tier can see Gold/Silver/Bronze jobs; Silver sees Silver/Bronze; Bronze sees Bronze only
5. Match jobs by required skills + experience tier
6. Sort by recency, limit results

### Test Attempt System:
- Max 2 attempts per test
- After 2 failures: 30-day cooldown (`cooldownUntil`)
- Passing awards a badge based on score tier
- Results tracked per job seeker per test

### Follow System:
- Request-based (Pending → Accepted/Rejected)
- Cross-collection support (job seeker can follow companies)
- Bidirectional tracking (following list + followers list)

### Employee System:
- Job seeker applies → Pending status
- Company accepts → Active status
- Company can terminate → Terminated status
- Only ex/current employees can review companies
